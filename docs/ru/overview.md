# Обзор проекта

[English version](../en/overview.md) · [README репозитория](../../README.ru.md)

NemotronDiarizationSharp — независимая неофициальная .NET-обёртка для NVIDIA Nemotron 3 Diarization. Она вызывает C ABI проекта [NVIDIA NeMo-Speech.cpp](https://github.com/NVIDIA/NeMo-Speech.cpp); инференс выполняется нативным движком.

## Текущий статус

Отдельная программа `tests/NemotronDiarizationSharp.RealSpeech` предназначена для короткого CPU-пилота на реальной речи. Она принимает внешние WAV и RTTM и диапазон фрагмента, сводит каналы к моно PCM float32, обрабатывает звук потоковыми секундными блоками через публичный API SDK, проверяет согласованность результата и сохраняет RTTM модели, обрезанную эталонную RTTM и JSON-отчёт. Программа не запускается обычным набором тестов и не рассчитывает DER: используйте проверенный внешний scorer с collar 0 и overlap включённым либо укажите `NOT_MEASURED`. Используется конфигурация `v3-streaming` с задержкой 30,4 с: speaker cache 264, FIFO 40, chunk 340, right context 40, update period 300. Подробности и пример запуска находятся в [README](../../README.ru.md).

В репозитории находится проверенный proof of concept для Windows x64 CPU и локально проверенный сценарий CUDA. Все управляемые проекты нацелены на .NET 10 LTS. Оба нативных runtime закреплены на NeMo-Speech.cpp v0.2.0. Запись и потоковый инференс CUDA завершились на одном компьютере с NVIDIA GPU; совместимость с другими GPU и драйверами, Linux и Vulkan не проверена. Проверка использует локальные DLL и отдельно предоставляемые модель GGUF и PCM-файл; нативные бинарные файлы исключены из репозитория, поскольку лицензии на распространение ещё не проверены. Кандидат managed SDK `0.1.0-preview.1` проверен локально; проекты native runtime и AllRuntimes не входят в prerelease и не публиковались.

Пакет `NemotronDiarizationSharp` содержит только managed SDK и не зависит от runtime конкретного backend. Он не включает native-бинарники или модель. Приложения должны отдельно предоставить совместимый runtime и модель. Локальные проекты пакетов CPU/CUDA runtime недоступны в NuGet, а права на распространение native-бинарных файлов не проверены. См. [выбор backend и структура пакетов](../en/multi-runtime.md).

Это независимый неофициальный проект, не являющийся продуктом NVIDIA и не одобренный NVIDIA.

## Ревизии результатов и управляемая постобработка

Добавленный API `ReadResultUpdates()` сообщает новые и изменённые кадры вероятностей вместе с актуальным списком сегментов, который заменяет предыдущий; прежний `ReadNewFrames()` остаётся добавочным. Update содержит сведения о разрывах и покрытии сравнения, но native ABI не предоставляет маркер стабильного кадра, поэтому нефинальные результаты предварительны, а уплотнение может скрыть ревизии. `DiarizationProbabilityHistory` применяет последовательные обновления к явно ограниченной или полностью хранимой в памяти истории и принимает непрерывные восстановленные извне пакеты до привязки live-потока. `DiarizationPostprocessor` предоставляет отдельную управляемую сегментацию и запись RTTM в writer вызывающего кода. `ProcessStreamAsync()` выдаёт результаты по запросу потребителя, обеспечивает backpressure, описывает границы отмены и выдаёт финальный результат при нормальном завершении источника; native-вызовы остаются синхронными и не прерываются. См. [контракты API и компилируемые примеры SDK](sdk-guide.md#результаты-с-ревизиями-и-управляемая-постобработка). Примеры компилируются в управляемых тестах; выполняется только синтетический пример постобработки, без native inference.

## Консоль WAV в RTTM

`examples/NemotronDiarizationSharp.Console` принимает обязательные пути `--model`, `--input` WAV и `--output` RTTM. По умолчанию используются CPU, финальная native-сегментация и секундные фрагменты декодированного аудио. `--backend cuda` явно выбирает CUDA (устройство 0 по умолчанию); `--gpu-device` разрешён только для CUDA. Существующий совместимый локальный runtime со всеми зависимостями выбирается через `--native-dir` или `NEMOTONDIARIZATIONSHARP_NATIVE_DIR` до первого нативного обращения; перехода на другой backend нет. См. [команды и полный список параметров SDK](sdk-guide.md#консоль-wav-в-rttm), включая `--segmentation`, `--recording-id`, `--chunk-frames` (1..96000) и отдельный вызов `--help`. Коды завершения: 0 - успех/справка, 2 - параметры/предварительная проверка, 1 - обработка/runtime/экспорт.

WAV reader SDK поддерживает обычные файлы с seek в формате RIFF/WAVE при 8000-96000 Гц: unsigned PCM8, signed PCM16/24/32 и IEEE float32. Требуются непустые полные кадры и уникальные chunks формата/данных; проверяются границы RIFF/chunk/padding, выравнивание и byte rate. Сжатое аудио, extensible WAV, RIFX и RF64 отклоняются. Каналы сводятся арифметическим средним; конечные WAV float ограничиваются `[-1,1]` до усреднения, NaN/infinity отклоняются. Исходная частота передаётся без managed-ресемплинга. До загрузки модели выполняется полный проход декодирования с ограниченным буфером, затем файл открывается повторно для последовательной потоковой обработки; вся PCM-запись не выделяется в памяти. Прежние три позиционных raw-float аргумента сохранены: ограниченные чтения, неизменные конечные амплитуды и финальные native-сегменты в stdout.

Режим native экспортирует сегменты финального snapshot после `Finish()`. Managed вызывает строгие обновления ревизий после каждого push/finish, применяет наблюдаемые изменения к полной `DiarizationProbabilityHistory(null)`, требует полного покрытия кадров и сегментирует финальную копию. Разрывы приводят к явной ошибке; полная история вероятностей и копирование растут с длительностью. Уплотнение может скрыть старые ревизии, а захваченное покрытие не гарантирует стабильность. Оба режима сохраняют перекрытия и абсолютное время кадров; шаг модели может вывести границы за длительность аудио. SDK writer RTTM использует канал 1 и `speaker_N` с нумерацией от единицы; токен записи по умолчанию берётся из имени файла с заменой пробельных/управляющих символов. Папка результата должна существовать. Успешный экспорт атомарно заменяет файл через временный файл в той же папке; при ошибке прежний результат сохраняется. Результат не может совпадать с моделью/аудио; все три пути и их родительские папки отклоняют ссылки, junctions и reparse points. Проверки не гарантируют защиту от конкурентных изменений файловой системы.

Managed-тесты декодера и сценариев проверяют детерминированную обработку входа. Для native inference нужны отдельные runtime и модель; локальные результаты не подтверждают точность или широкую совместимость с GPU.

## Входные данные runtime

Тест нативного инференса получает пути к модели и PCM из переменных `NEMOTONDIARIZATIONSHARP_MODEL` и `NEMOTONDIARIZATIONSHARP_PCM_F32LE`. Старые имена `NEMOTONSHARP_MODEL` и `NEMOTONSHARP_PCM_F32LE` продолжают работать как резервные. Путь к нативным библиотекам можно задать через `NEMOTONDIARIZATIONSHARP_NATIVE_DIR`; если эта переменная не задана, принимается прежнее имя `NEMOTONSHARP_NATIVE_DIR`.

Необязательный консольный harness `tests/NemotronDiarizationSharp.LongRun` использует эти переменные процесса, проверяет существующие модель и PCM-файл, циклически подаёт 8-секундный PCM ограниченными фрагментами, проверяет непрерывность кадров и сохранённую историю, а также выводит показатели памяти процесса и .NET и пропускной способности. Он не входит в обычный набор тестов; повторяющийся звук не проверяет точность диаризации. Команды короткой проверки и 25-минутного запуска для PowerShell приведены в [README](sdk-guide.md#необязательная-длительная-диагностика). Harness использует публичный SDK; `ReadNewFrames()` при каждом вызове копирует всё сохранённое нативное окно вероятностей, поэтому частота опроса влияет на накладные расходы диагностики.

Веса модели по умолчанию остаются вне пакета. У runtime и модели отдельные лицензионные условия; их необходимо проверить до распространения.

## Управляемый API

Для совместимых моделей Nemotron-3 V3 `DiarizationPresets` предоставляет `Nemotron3OfflineStyle`, `Nemotron3LowLatency`, `Nemotron3VeryLowLatency` и `Nemotron3UltraLowLatency` по [официальной таблице NVIDIA](https://huggingface.co/nvidia/Nemotron-3-Diarization): `(кэш говорящих, FIFO, chunk, правый контекст, период обновления)` — `(264,40,340,40,300)`, `(264,264,9,4,222)`, `(264,264,6,2,222)` и `(264,264,3,1,222)`. Геометрия задаётся грубыми кадрами encoder по 80 мс; задержки chunk плюс правый контекст равны 30,4 с, 1,04 с, 0,64 с и 0,32 с. Профили используют native `v3-streaming` и managed-переопределения; левый контекст сохраняет V3 streaming default 0. Пользовательская геометрия доступна через `DiarizationModelOptions` и JSON. Это профили потоковой обработки, включая метку NVIDIA “Very high latency (offline)”; они не выбирают `ProcessOffline()`. Таблица не рекомендует пороги сегментации, поэтому остаются native defaults.

API загружает модель, открывает поток, принимает моно PCM float32 и предоставляет вероятности по кадрам, временные метки и сегменты диаризации. Вход должен содержать конечные значения, которые следует нормализовать в диапазон `[-1, 1]`, и сопровождаться явной частотой от 8 до 96 кГц. Native runtime пересэмплирует звук к частоте модели; SDK также читает поддерживаемые RIFF/WAVE через DiarizationWaveReader и ProcessWaveFile; другие кодеки и контейнеры требуют внешнего декодирования. `DiarizationModel.Load(path)` по умолчанию использует Auto для backend и геометрию потоковой обработки native runtime. `GpuDeviceIndex` выбирает CUDA-устройство, но не backend; null означает устройство 0, если выбрана CUDA. Значения preset (`streaming`, `offline`, `v3-streaming`, `v3-offline`) настраивают геометрию потоковой обработки; имена `offline` не выбирают отдельный API `ProcessOffline`.

`ProcessOffline` обрабатывает один вход целиком как stateless full-attention задачу, возвращает финальный snapshot с историей от кадра 0 и ограничен позиционной ёмкостью модели. `DiarizationSegmentationOptions` можно передать при создании потокового snapshot или offline-результата. `DiarizationStream.Push` требует одинаковую частоту для всего потока; `Finish` вызывается явно и повторный вызов безопасно возвращается без действия. Нативное уплотнение истории вероятностей выполняется только при обнаружении подходящего интервала, когда все говорящие молчат; оно не гарантировано через фиксированную длительность записи и не задаёт жёсткий предел нативной памяти. После уплотнения пользовательские параметры применяются только к сохранённой части; завершённые ранее сегменты не пересчитываются. Нативное уплотнение независимо от лимитов хранения в управляемом `DiarizationProbabilityHistory`. `DiarizationStream.ReadNewFrames()` возвращает принадлежащие вызывающему коду `DiarizationFrameBatch` с абсолютными индексами кадров и отдельным курсором этого потока; snapshot не сдвигает его, а финальные кадры можно прочитать после `Finish()`. При разрыве из-за уплотнения выбрасывается `DiarizationFrameHistoryGapException` с потерянным диапазоном. Читайте кадры достаточно часто: сегменты не восстанавливают исходные вероятности. Native v0.2.0 копирует всё сохранённое окно при каждом чтении, даже если новый пакет меньше. Пакет фиксирует значения на момент чтения, поскольку ABI не гарантирует неизменность ранее выданных вероятностей. Индексы каналов вероятностей начинаются с нуля; ID говорящего в сегменте соответствует нативной нумерации с единицы.

`DiarizationStream.PushChunksAsync()` последовательно читает `IAsyncEnumerable<ReadOnlyMemory<float>>` и держит в обработке только один фрагмент, без очереди на стороне API. Каждый синхронный нативный вызов выполняется в рабочем потоке и завершается до запроса следующего фрагмента. Токен передаётся источнику и проверяется между вызовами; источник, игнорирующий отмену, может задержать её, а уже выданный фрагмент обрабатывается полностью. Начавшуюся нативную операцию прервать нельзя. Завершение и отмена не вызывают `Finish()`. При отмене и ошибках источника или входных данных обработанный префикс остаётся пригодным; после ошибки нативного `Push` поток необходимо освободить. Пока асинхронная последовательность активна, конфликтующие операции потока, включая освобождение и второй асинхронный вызов, явно отклоняются. Не изменяйте память выданных фрагментов до завершения задачи. SafeHandle потока удерживает нативную модель, даже если managed-модель освобождена раньше. Явно освобождайте модель и поток. API не обещает общей потокобезопасности; выполняйте операции последовательно и ожидайте завершения асинхронной подачи перед использованием или освобождением того же экземпляра. Отсутствующая модель приводит к `FileNotFoundException`; неверная частота и не конечные значения — к исключениям аргументов; ошибка нативного вызова передаётся как `InvalidOperationException`. При чтении кадров перехватывайте `DiarizationFrameHistoryGapException` до базового `InvalidOperationException`. Отсутствующая или несовместимая DLL может привести к `DllNotFoundException` или `BadImageFormatException`. См. также [архитектуру](architecture.md). Пример в [README](../../README.ru.md#быстрый-старт) проверен вручную; тесты контракта проверяют сигнатуры публичного API.

`NEMOTONDIARIZATIONSHARP_NATIVE_DIR`, если задана, должна содержать абсолютный путь к папке выбранного runtime с entry DLL и зависимостями. Иначе loader проверяет стандартные каталоги CPU и CUDA в папке приложения; файлы туда должно поместить само приложение, поскольку native runtime NuGet-пакеты недоступны. Затем проверяются совместимые legacy-каталоги CPU. C ABI entry DLL загружается по абсолютному пути с поиском зависимостей в этой папке и System32. Backend фиксируется для процесса; после начала нативной загрузки переключение не выполняется. Загрузка проверена на Windows x64; целевая платформа `net10.0` не подтверждает поддержку Linux. Права на распространение native binaries не проверены.

## Выбор CUDA-устройства

`Backend` по умолчанию равен `Auto`; `GpuDeviceIndex` не выбирает backend, а задаёт CUDA-устройство (null означает 0, если выбрана CUDA). `Backend = Cpu` или `Backend = Cuda` принудительно требует выбранный runtime без переключения на другой. Auto проверяет устройство через `nvidia-smi` до загрузки runtime, но это не гарантирует совместимость драйвера. Диагностический хост `tests/NemotronDiarizationSharp.CudaPilot` запускает inference только по явному параметру `--run-smoke` и требует отдельно подготовленные CUDA runtime-файлы. Inference проверялся на одном локальном тестовом хосте; совместимость с другими GPU и драйверами не подтверждена. Распространение бинарных файлов остаётся заблокированным до проверки лицензий.
