# Архитектура

[English version](../en/architecture.md) · [Обзор проекта](overview.md)

NemotronDiarizationSharp — независимая .NET-обёртка над официальным C ABI NeMo-Speech.cpp. Управляемый слой владеет временем жизни модели и потоков, передаёт PCM float32 и предоставляет вероятности говорящих, временные метки кадров и сегменты, полученные от runtime. Нейросетевой инференс остаётся в нативном движке.

## Проекты

- `NemotronDiarizationSharp` — публичный управляемый API и нативный interop.
- `NemotronDiarizationSharp.Runtime.Cpu` — проект пакета runtime для Windows x64 CPU. Его локальные нативные бинарные файлы исключены из публичного репозитория до проверки лицензий на распространение.
- `NemotronDiarizationSharp.Tests` — тесты управляемого поведения и нативного инференса на Windows.
- `NemotronDiarizationSharp.Console` — пример запуска инференса из командной строки.

## Нативная граница и загрузка библиотек

Сигнатуры interop соответствуют закреплённому C API NVIDIA NeMo-Speech.cpp. Имя нативной библиотеки и точки входа — идентификаторы upstream; они не меняются. В Windows непустая `NEMOTONDIARIZATIONSHARP_NATIVE_DIR` имеет приоритет над каталогом приложения и должна содержать абсолютный путь к существующему каталогу с `nemo_speech_asr_c.dll`; неверная явная настройка приводит к ошибке без перехода к запасному варианту. Если переменная не задана или пуста, обёртка проверяет каталог приложения, затем каталог из прежней `NEMOTONSHARP_NATIVE_DIR` и, наконец, системный загрузчик.

## Runtime и модель

Проверенная конфигурация — Windows x64 CPU с имеющимся закреплённым runtime и отдельно предоставляемой моделью GGUF. Нативный тест использует моно PCM float32 little-endian с частотой 16 кГц. Веса модели не включаются в NuGet-пакеты. Нативные бинарные файлы являются локальными входными данными для разработки и не должны распространяться до завершения проверки лицензий.

Linux, GPU-бэкенды, дополнительные аудиоформаты и загрузка пакетов в чистом окружении не проверялись. Проект не заявляет такую поддержку.

## Ресурсы

Модель владеет нативным дескриптором модели, а потоки — дескрипторами потоков. API и тесты явно освобождают их. Снимки результатов предоставляют вероятности по кадрам, временные метки и сегменты, возвращённые нативным API. Нативный поток может уплотнить историю вероятностей только при обнаружении подходящего интервала тишины у всех говорящих; уплотнение не гарантировано при фиксированной длительности записи и не задаёт жёсткий предел нативной памяти. Такое уплотнение независимо от лимитов хранения в управляемом `DiarizationProbabilityHistory`. В остальном история потоковой обработки и перекрывающаяся активность говорящих следуют поведению закреплённого нативного runtime.

Проверка входных данных выполняется до нативного Push, поэтому неверная частота дискретизации, её изменение в ходе потока и бесконечные или NaN-сэмплы не мешают исправить вызов и продолжить работу с потоком. Если нативный Push или Finish возвращает ошибку либо interop-вызов выбрасывает исключение, управляемый поток переходит в терминальное состояние ошибки: нативная обработка могла изменить состояние до сообщения об ошибке. После этого поток нужно освободить; новые Push, снимки, чтение кадров и Finish отклоняются. Успешный Finish идемпотентен. После Finish управляемый API отклоняет Push.
