# Project overview

[Русская версия](../ru/overview.md) · [Repository README](../../README.md)

NemotronDiarizationSharp is an independent, unofficial .NET wrapper for NVIDIA Nemotron 3 Diarization. It calls the C ABI exposed by [NVIDIA NeMo-Speech.cpp](https://github.com/NVIDIA/NeMo-Speech.cpp); inference remains in the native engine.

## Current status

The repository contains a verified Windows x64 CPU proof of concept and a locally validated Windows x64 CUDA path. All managed projects target .NET 10 LTS. Both native runtimes are pinned to NeMo-Speech.cpp v0.2.0. CUDA recording and streaming inference completed on one NVIDIA GPU host; general GPU/driver compatibility, Linux, and Vulkan remain unverified. Validation uses local native DLLs and a user-supplied GGUF model and PCM fixture. Native binaries are excluded because redistribution licensing has not been cleared. Managed SDK `0.1.0-preview.1` is published; native runtime and AllRuntimes package projects remain unpublished.

The `NemotronDiarizationSharp` package contains only the managed SDK and has no backend runtime package dependency. It does not include native binaries or model weights. Applications must provide a compatible runtime and model separately. The local CPU/CUDA runtime package projects are not available as NuGet packages, and native redistribution rights have not been cleared. See [multi-runtime selection and package layout](multi-runtime.md).

The project is independent and unofficial. It is not an NVIDIA product or endorsed by NVIDIA.

## Revision-aware results and managed postprocessing

The additive `ReadResultUpdates()` API reports new and revised probability frames with the latest replaceable segment list; the older `ReadNewFrames()` API remains append-only. Updates expose gaps and comparison coverage, but the native ABI provides no stable-frame watermark, so non-final results are provisional and compaction can hide revisions. `DiarizationProbabilityHistory` applies consecutive updates to explicitly bounded or full in-memory history and can accept contiguous externally restored batches before live binding. `DiarizationPostprocessor` offers a separate managed segmentation algorithm and caller-owned RTTM writing. `ProcessStreamAsync()` provides pull-based updates, backpressure, cancellation boundaries, and a final update after normal source completion; native calls remain synchronous and noninterruptible. See the [SDK API contracts and compiled examples](sdk-guide.md#revision-aware-results-and-managed-postprocessing). These examples are compiled with managed tests; only the synthetic postprocessing example executes, without native inference.

## WAV-to-RTTM console

`examples/NemotronDiarizationSharp.Console` accepts required `--model`, `--input` WAV and `--output` RTTM paths. It defaults to CPU, final native segmentation and one-second decoded audio chunks. Optional `--backend cuda` explicitly selects CUDA (device 0 by default); `--gpu-device` is allowed only with CUDA. Use an existing compatible local runtime through `--native-dir` or `NEMOTONDIARIZATIONSHARP_NATIVE_DIR` before first native resolution, with its matching dependencies; selection does not fall back. See the [SDK guide commands and complete options](sdk-guide.md#wav-to-rttm-console) for `--segmentation`, `--recording-id`, `--chunk-frames` (1..96000) and standalone `--help`. Exit codes are 0 for success/help, 2 for options/preflight errors and 1 for processing/runtime/export errors.

The SDK WAV reader supports seekable regular RIFF/WAVE files at 8000-96000 Hz: unsigned PCM8, signed PCM16/24/32 and IEEE float32. It requires nonempty complete audio frames and unique format/data chunks, validates RIFF/chunk/padding/alignment/byte-rate bounds and rejects compressed audio, extensible WAV, RIFX and RF64. Multichannel audio uses arithmetic mean downmix; finite WAV float channels are clipped to `[-1,1]` before averaging, and NaN/infinity is rejected. It forwards the source rate without managed resampling. A complete bounded preflight decoding pass precedes model loading, followed by reopening and sequential streaming; no whole PCM recording is allocated. The three positional raw-float arguments remain supported with bounded reads, unchanged finite amplitudes and final native segments on stdout.

Native mode exports final snapshot segments after `Finish()`. Managed mode polls strict revision updates after every push/finish, applies observed revisions to full `DiarizationProbabilityHistory(null)`, requires complete frame coverage and segments a final owned copy. Gaps fail visibly; full probability retention and final copying grow with duration. Compaction can hide older revisions, and captured coverage does not guarantee stability. Both modes preserve overlaps and absolute frame timing; model cadence can extend timing beyond audio duration. The SDK RTTM writer uses channel 1 and one-based `speaker_N`; the default recording token comes from the filename with whitespace/control characters replaced. An existing output directory is required. Successful export atomically replaces output through a temporary file in that directory; failures preserve previous output. Model/input/output paths must differ where output could overwrite a source, and all three paths and their ancestors reject links, junctions and reparse points. Concurrent filesystem changes are outside these checks' guarantees.

Managed decoder and workflow tests cover deterministic input handling. Native inference requires separate runtime/model inputs; local results do not establish accuracy or broad GPU compatibility.

## Runtime inputs

The native smoke test reads the model and PCM paths from `NEMOTONDIARIZATIONSHARP_MODEL` and `NEMOTONDIARIZATIONSHARP_PCM_F32LE`. The earlier `NEMOTONSHARP_MODEL` and `NEMOTONSHARP_PCM_F32LE` names are still accepted as fallbacks. Native library resolution can be directed with `NEMOTONDIARIZATIONSHARP_NATIVE_DIR`, with `NEMOTONSHARP_NATIVE_DIR` retained as a fallback.

The opt-in `tests/NemotronDiarizationSharp.LongRun` console harness uses these process environment variables to validate the existing model and PCM fixture, cycle the 8-second fixture through bounded chunks, inspect frame continuity and retained history, and report managed/process memory and throughput. It is not part of the ordinary test suite and repeated audio is not an accuracy benchmark. See the [SDK guide long-run instructions](sdk-guide.md#opt-in-long-run-diagnostics) for preflight and 25-minute PowerShell commands. The harness uses public SDK APIs; `ReadNewFrames()` copies the entire retained native probability window on every read, so polling cadence affects diagnostic overhead.

The opt-in `tests/NemotronDiarizationSharp.RealSpeech` console harness accepts external RIFF/WAVE audio and reference RTTM paths plus an excerpt range. It downmixes channels to mono float32, streams one-second blocks through the public SDK API, checks output consistency, and exports prediction and cropped-reference RTTM files with a JSON report. It remains outside the normal test suite and does not calculate DER; use a trusted external scorer with collar 0 and overlap enabled, or mark DER `NOT_MEASURED`. It uses the verified `v3-streaming` 30.4-second geometry (speaker cache 264, FIFO 40, chunk 340, right context 40, update period 300). See the README for the command line and WAV format limits.

Model weights stay outside the package by default. The native runtime and model have separate license terms that must be reviewed before redistribution.

## Managed API

`DiarizationModelOptions.Backend` defaults to `Auto`; the first native initialization prefers CUDA when `nvidia-smi` reports a device, then selects CPU when available. `Backend = Cpu` and `Backend = Cuda` require that backend and do not fall back. `GpuDeviceIndex` selects a CUDA device but does not select the backend; null means device 0 when CUDA is selected. A successful pre-load device check does not guarantee driver compatibility. The selected runtime is fixed for the process. Local evaluation does not clear redistribution licensing or establish general CUDA support.

The API loads a model, opens a stream, accepts mono float32 PCM, and exposes frame probabilities, timestamps, and diarization segments. Input must contain finite values, should be normalized to `[-1, 1]`, and must include an explicit sample rate from 8 to 96 kHz. The native runtime resamples to the model rate; the SDK also reads supported RIFF/WAVE through DiarizationWaveReader and ProcessWaveFile; other codecs and containers require external decoding. `DiarizationModel.Load(path)` defaults to Auto backend selection and native-default streaming geometry. `GpuDeviceIndex` selects a CUDA device but does not select a backend; null means device 0 when CUDA is selected. Preset values (`streaming`, `offline`, `v3-streaming`, `v3-offline`) configure streaming geometry; the `offline` names do not select the separate `ProcessOffline` API.

For compatible Nemotron-3 V3 models, `DiarizationPresets` also exposes `Nemotron3OfflineStyle`, `Nemotron3LowLatency`, `Nemotron3VeryLowLatency`, and `Nemotron3UltraLowLatency`, matching the [official NVIDIA model-card table](https://huggingface.co/nvidia/Nemotron-3-Diarization): `(speaker cache, FIFO, chunk, right context, update period)` are `(264,40,340,40,300)`, `(264,264,9,4,222)`, `(264,264,6,2,222)`, and `(264,264,3,1,222)`. Geometry uses coarse 80 ms encoder frames; the corresponding chunk-plus-right-context latencies are 30.4 s, 1.04 s, 0.64 s, and 0.32 s. They use native `v3-streaming` plus managed geometry overrides; left context stays at its V3 streaming default of zero. Custom geometry remains available through `DiarizationModelOptions` and JSON. These are streaming profiles, including NVIDIA's “Very high latency (offline)” label; they do not select `ProcessOffline()`. The table does not recommend segmentation thresholds, so native segmentation defaults remain in effect.

`ProcessOffline` processes one complete input as a stateless full-attention job, returns a final snapshot beginning at frame zero, and is limited by model positional capacity. `DiarizationSegmentationOptions` can be passed to streaming snapshots or offline processing. `DiarizationStream.Push` requires one sample rate for the whole stream; `Finish` is explicit and idempotent. Native probability-history compaction is conditional on finding a suitable interval where all speakers are silent; it is not guaranteed at a fixed recording duration and does not establish a hard native-memory limit. Custom segment settings affect only the retained tail after compaction; previously finalized segments are not recomputed. Native compaction is independent of managed `DiarizationProbabilityHistory` retention limits. `DiarizationStream.ReadNewFrames()` returns owned `DiarizationFrameBatch` values with absolute frame indexes and a per-stream cursor; snapshots do not advance it, and final frames remain readable after `Finish()`. A compaction gap throws `DiarizationFrameHistoryGapException` with the lost range. Poll frequently enough to avoid gaps; finalized segments cannot recover raw probabilities. Native v0.2.0 copies the entire retained probability window per read, even when only a smaller batch is returned. Batches capture values at read time, because the ABI does not guarantee earlier probabilities remain immutable. Probability-channel indexes are zero-based; segment speaker IDs follow the native one-based numbering.

`DiarizationStream.PushChunksAsync()` sequentially consumes `IAsyncEnumerable<ReadOnlyMemory<float>>` with one outstanding chunk and no application-level queue. Each synchronous native push runs on a worker thread and completes before the source advances. Cancellation is passed to the source and checked between pushes; a source that ignores its token can delay cancellation, and a yielded chunk completes before cancellation is reported. Native work already in progress is not interruptible. Completion and cancellation do not call `Finish()`. Cancellation and source/input validation errors leave the completed prefix usable; a native push error requires disposing the stream. While the async sequence is active, conflicting stream operations, including disposal and another async push, fail explicitly. Do not mutate yielded buffers until the returned task completes. The stream SafeHandle retains the native model if the managed model is disposed first. Dispose both model and stream explicitly. The API does not promise general thread safety; sequence operations and await async pushes before using or disposing the same instance. A missing model file throws `FileNotFoundException`; invalid input uses argument exceptions; native failures are surfaced as `InvalidOperationException` with native error text. Catch `DiarizationFrameHistoryGapException` before that base exception. Missing/incompatible DLLs may raise `DllNotFoundException` or `BadImageFormatException`. See [architecture](architecture.md) for the managed/native boundary and current limits. The README quick start has a manually checked example; contract tests verify its public API signatures.

When `NEMOTONDIARIZATIONSHARP_NATIVE_DIR` is set, it must be an absolute directory containing the selected runtime's entry DLL and dependencies. Otherwise the loader checks the standard CPU and CUDA runtime directories under the application directory; the application must stage those files because native runtime NuGet packages are unavailable. It then checks compatible legacy CPU locations. The C ABI entry DLL is loaded by absolute path with dependency lookup scoped to that directory and System32. Backend selection is fixed for the process, and a native load failure does not trigger a switch. Current native loading is validated only on Windows x64. The managed `net10.0` target does not establish Linux support, and native binary redistribution is not legally cleared.
