## Redistribution readiness and release path

Some components have terms that can permit redistribution when their conditions are met: preserved NeMo/ggml and dependency notices include MIT/Apache materials, the CUDA 12.9.1 EULA lists CUDA Runtime and cuBLAS component families, and Microsoft publishes eligible Visual Studio Redistributable files. These terms do not clear the current package. Binary-specific applicability, build provenance, distributor eligibility, and downstream conditions still need review.

Start with CPU because the five selected engine DLLs byte-match the recorded official v0.2.0 release ZIP and the package leaves Microsoft CRT/OpenMP as a consumer-installed prerequisite. Before publication, obtain authoritative build/composition evidence (especially KenLM/LGPL and static dependency coverage), complete applicable notices and source/relink materials, and resolve Microsoft redistribution eligibility and the supported runtime floor. If that evidence cannot be obtained, replace the CPU binaries with a reproducible build from pinned source and reviewed inputs. Then build and validate a clean external consumer package. CUDA should follow separately after authenticated/reproducible build provenance, full component/notice coverage, explicit NVIDIA CUDA application-distribution review for reusable NuGet delivery, and Microsoft eligibility for the bundled VC145 CRT and VC143 OpenMP files. Defer AllRuntimes until CPU and CUDA packages are independently cleared. These steps describe readiness; no native publication is authorized.

Inference still requires a separately obtained compatible runtime and model. Model weights remain external, and no model redistribution right is assumed.

Windows x64 with .NET 10 is the validated environment. CPU and CUDA recording and streaming inference have completed in local validation. This does not establish general GPU or driver compatibility, clean-machine installation, Linux support, multi-GPU behavior, or CUDA kernel execution attribution. Those areas remain unverified. Runtime packages target Windows x64 and do not filter assets for unsupported consumer platforms.

Model weights are external and remain subject to their own terms; no model redistribution right is assumed. The CUDA driver library `nvcuda.dll` is supplied by the installed driver and is not packaged. Do not copy operating-system DLLs into runtime packages. Required upstream `LICENSE`, `NOTICE`, `THIRD_PARTY_NOTICES.md`, component notices, and the CUDA terms must remain with any applicable distribution. Successful restore, build, pack, or publish does not establish permission to redistribute these files.

The runtime build targets copy native DLLs, not their license materials, to application output. Distributors of any authorized runtime package must carry the applicable `licenses/` files as required by those terms. The relative links inside the upstream notice documents refer to paths in their complete source trees; this repository contains only a scoped source snapshot. The relevant local license and notice texts are preserved alongside the package, and the partial-snapshot boundary is recorded in [upstream license evidence](upstream-licenses.md).
